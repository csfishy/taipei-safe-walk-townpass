# 附近通知安全狀態

PR #41 修正後維持 **BLOCKED**。目前沒有可驗證使用者身分與協助者資格的附近通知後端；不得將 API 連線成功、匿名 UUID、公開 key、使用者同意或 `NEARBY_LIVE_ENABLED` 當成授權證據。

`SupabaseNearbyAlertTransport` 已停止所有 HTTP 呼叫。服務在取得 GPS 前回傳 Unavailable；附近接收、加入協助者及發送均無法由環境旗標開啟。測試中的 fake transport 僅用於取消與流程契約驗證，不是正式替代後端。已經提交至其他後端的操作無法由本機取消回收；取消只阻止後續副作用並忽略遲到結果。

## 舊後端的處置

`supabase/nearby_emergency.sql` 現在只撤銷三個確切舊 RPC 簽章對 `PUBLIC`、`anon`、`authenticated`、`service_role` 的執行權。不存在的函式與角色會略過；如果繼承權限仍允許 API 角色執行，交易失敗，不能視為完成隔離。它不新增資料表、不建立替代 RPC、不刪除任何資料，也不觸及犯罪參考資料或 Demo schema。

**本次未在遠端執行 SQL，沒有查讀或變更真實位置資料。** 程式封鎖不代表先前部署的資料庫已撤權。若曾部署舊 RPC，維運者須先確認目標專案與實際權限，依既有 Level C 授權與安全審查手動執行撤權，再驗證匿名／登入角色無法呼叫。不要將此腳本加入 CI、build、App 啟動或 Demo reset。舊位置資料的保留與刪除須另訂經核准方案；本修正不聲稱已清除。

## 重新啟用的必要證據

- 後端驗證登入憑證並由可信 session 決定身分；不接受用戶傳入 UUID 當作 ownership。
- 伺服器維護與核對協助者資格、有效同意及接收授權；驗證他人無法查詢或修改位置、通知。
- 受限 RPC／RLS、角色與函式權限、參數與位置新鮮度驗證、限流及防重送。
- 明確的通知與位置 TTL、保留刪除及撤回流程，包含失敗時的處理與稽核。
- 隔離後端的越權／過期／濫用測試、安全審查、實際後端與裝置驗收，並記錄部署版本與授權。

完成上述證據後，另以受審查的 authenticated transport 與後端替換退役實作；不要新增 client boolean 來解鎖舊 RPC。緊急聯絡人或電話等其他能力依各自同意與驗收獨立運作。

## 隔離簡訊測試入口

`nearby_live_test_main.dart` 不再載入匿名 UUID、Supabase URL 或 key。僅在明確使用 `SMS_LIVE_TEST_ENABLED=true` 啟動隔離入口時配置聯絡人簡訊；附近服務仍不可用。定位與將精確座標傳給已儲存聯絡人的同意分開，取得位置後及每個非同步步驟後重新檢查。取消、撤回同意、離開頁面或切換背景會停止後續步驟；恢復前景不會自動恢復同意或接收。

Android 缺少 SEND_SMS 權限時會向系統要求權限，本次不提交簡訊，授權後也不自動重送；永久拒絕時可能須到系統設定調整，不保證權限視窗出現。整合 #42 的明確提交狀態後，`handedToSystem` 只表示系統提交呼叫返回，沒有發送／送達回執，不代表聯絡人收到，也不代表警消受理。權限不足、無效要求與平台不支援分別呈現；原生例外、逾時或不明回應只表示結果未確認，不能斷言完全未送出。iOS 未提供此傳送能力。測試沒有發出真實簡訊、取得真實 GPS 或通知任何協助者；實機權限、電信結果與送達仍未驗證。
